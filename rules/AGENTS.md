# 顶会论文多轮盲审自进化守则 (`paper-review-evolve`)

当用户在学术论文项目（含 `.tex`、`paper/`、`paper_*/`）中要求「模拟顶会盲审」「多轮审稿修改直至分数收敛」「按 S&P / CCS / ICML / NeurIPS 等顶会标准打磨论文」或运行 `/goal` 持续优化论文质量时，必须遵守以下五条铁律：

1. **零上下文盲审隔离（严禁作者自审自评）**：
   - 严禁在当前主会话中自己扮演审稿人给自己刚改完的论文打分。
   - 每一轮盲审必须调用 `invoke_subagent(TypeName="research")` 启动全新的独立只读子代理；Prompt 中只能提供编译后的匿名产物路径（`main.pdf`、`main.tex`、数据脚本与审稿包）与该顶会 PC 评审维度，严禁透露前几轮分数、修改历史或“请给高分”等暗示。

2. **三正交 PC 人设 + 近两年顶会标杆锚定**：
   - 首轮盲审前必须检索目标顶会近两年的同方向代表作（Exemplars），明确该赛道的实验模型规模、基线标准与理论门槛。
   - 每一轮必须并发启动 **3 位视角正交的 PC 审稿人**（由 `review_cli.py prompts` 生成或按 `venue_profiles.md` 配置）：① 理论/形式化/密码学或数学证明审稿人、② 系统实现/开销/代码与数据复现审计审稿人、③ 实验泛化/统计显著性/威胁或假设边界审稿人。

3. **重证据轻话术 & 云端/Colab 优先算力纪律**：
   - 收到盲审 Major/Minor 缺陷后，必须先按 `A 类（实验/规模短板）`、`B 类（理论/证明短板）`、`C 类（诚实边界界定）` 分类：
     - 凡属 **A 类实验或模型规模短板**（如模型停留于 Toy 规模、缺旗舰大模型验证、缺 OOD 数据集），优先调度云端/Colab 算力（或读取已同步的云端实验 JSON）补齐真实数据，**严禁调用本地机器跑高负载大模型训练/推理阻塞工作区**，更严禁在不动实验的情况下靠堆砌辩解文字糊弄审稿人。

4. **单源真值与盲审前机检棘轮（Audit Ratchet）**：
   - 严禁在 `.tex` 中手敲散落的野生实验数字；所有实验指标必须走 `JSON 真值 -> 资产脚本自动生成宏与表格 -> LaTeX 编译与 PDF 元数据脱敏` 闭环。
   - 在发起任何一轮新盲审或向用户交付前，必须运行 `review_cli.py audit`（及项目自带 `audit*.py`），确保：**0 未定义引用、`Overfull \hbox <= 8.0pt`、页数不超顶会红线、无 `\resizebox{\columnwidth}` 强行缩放表格、PDF 无作者/时区/PTEX 元数据残留**。

5. **单调收敛与终轮「反臃肿瘦身（De-Bloating）」**：
   - 每轮审稿结果必须通过 `review_cli.py record` 记入 `review_ledger.json`，持续迭代直至同时满足：**① 3 位审稿人全员给出正向录用分（Accept 区间）、② 0 个阻断性 Major、③ 连续两轮平均分波动 `< 0.3`**。
   - 收敛后定稿前必须执行 `review_cli.py debloat-check` 反臃肿瘦身：
     - **摘要精炼至 150–220 词**（删去各轮追加的碎片化括号与参数报菜名）；
     - **表格以核心目标模型（Target-First）为首列、按最大旗舰规模（如 70B → 4B）降序排列**；
     - 首屏动机图与核心架构图联动 `paper-figure-studio` 确保可编辑 `.pptx` + 真矢量 `.pdf` 双交付。

# 顶会论文配图生成守则 (`paper-figure-studio`)

当用户在学术论文项目（含 `.tex` / `paper/`）中要求绘制或精修 Intro 动机图、Method Overview 方法架构图或机制分镜图时，遵守以下四条铁律：

1. **双交付物 PPT 优先路线（可编辑 `.pptx` + 真矢量 `.pdf`）**：
   - 除基于真实实验 CSV/JSONL 绘制的定量曲线/柱状图继续使用 `Matplotlib`（`pdf.fonttype = 42`）外，架构总览图、痛点对比图与机制分镜图默认走 `paper-figure-studio` 技能的 **`python-pptx`（OOXML 原生公式）→ `LibreOffice` 静默导出紧致裁切矢量 `.pdf` → `PyMuPDF` 渲染回看自检** 管线，同时向论文目录交付 100% 鼠标可拖拽改字的 `.pptx` 与可直接 `\includegraphics` 的真矢量 `.pdf`。

2. **AI 生图严格限缩于「局部纯视觉小素材」**：
   - 严禁调用 `image-generator` 直接生成整张方法架构图、带角标数学公式或因果连接箭头（位图模型易吞掉关键角标如 $<i$ 且不可编辑）。
   - 仅允许用 `image-generator` 生成无文字、纯白底局部插画/图标/样本 Patch，经 `ai_asset_prep.py` 自动去白底裁切后再嵌入 `.pptx` 矢量骨架。

3. **论文真值符号与 `2.0x` 缩印字号对齐**：
   - 动笔前先用 `paper_context.py` 读取目标论文的宏包版心宽度（如 ICML 双栏 `6.75in` / 单栏 `3.25in`）与 `\newcommand` 真值宏、核心公式符号，确保图内张量角标与正文 100% 逐字符一致，严禁臆造野生符号或假实验数字。
   - 采用 `2.0x` 画布缩比法则（跨双栏画布宽 `13.5in`、单栏画布宽 `6.5in`，PPT 正文字号 `14–18pt`，缩印至论文后等效 `7–9pt`），严禁灰底黑字、严禁在图内顶部重复写大标题（标题归 LaTeX `\caption`）。

4. **强制执行「渲染回看自检闭环（Render-Inspect-Fix）」**：
   - 严禁只跑完生成脚本就直接向用户交图！每次生成或修改 `.pptx` 后必须运行 `export_inspect.py`，并用 `read_file` 亲眼核验生成的 `<stem>_preview.png`、带英寸坐标尺的 `<stem>_ruler_grid.png` 与双栏原大模拟页 `<stem>_icml_mockup.png`；若机检报告 `audit_report.json` 存在文字意外折行、重叠、越界或缩印字号过小，必须修正重跑直至零硬伤通过。
